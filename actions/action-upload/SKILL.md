# Action: Upload

## Action type and browser requirement

| Property | Value |
|----------|-------|
| `action_type` | `upload` |
| Requires browser | Yes |

## What it does

Uploads a file to an `<input type="file">` element on the page. The runtime locates the file input via CSS selectors, then sets the file programmatically (bypassing the OS file picker dialog). The file can come from the current automation session (e.g., a downloaded file from a previous step) or from persistent file storage.

## Required fields

| Field | Type | Description |
|-------|------|-------------|
| `step_number` | number | Sequential step position starting from 1 |
| `action_type` | string | Must be `"upload"` |
| `stepId` | string | Unique step identifier (format: `step-XXXXX`, hex chars) |
| `timestamp` | number | Unix timestamp in milliseconds |

## Optional fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `selectors` | string[] | `[]` | CSS selectors to locate the `<input type="file">` element. Tried in order. |
| `value` | string | `""` | The filename to upload. |
| `uploadType` | string | `"file"` | Source of the file: `"session"` for a file from the current session, `"file"` for a file from persistent storage. |

## Complete JSON example

```json
{
  "step_number": 4,
  "action_type": "upload",
  "stepId": "step-8fe31",
  "timestamp": 1710000000000,
  "selectors": [
    "input[type='file']#document-upload",
    "input[type='file']"
  ],
  "value": "invoice-2024-03.pdf",
  "uploadType": "file"
}
```

## Field details

### `value`
The filename of the file to upload. This should be the name of a file available in either the session's working directory or persistent storage, depending on `uploadType`.

### `uploadType`
Determines where the runtime looks for the file:
- `"session"` — The file was produced during the current automation run (e.g., downloaded by a previous `download` step or generated by a `generate_media` step). Looked up in the session's temporary working directory.
- `"file"` — The file is stored in the persistent file storage associated with the automation. This is the default.

### `selectors`
Must point to an `<input type="file">` element. If the file input is hidden (common with styled upload buttons), the selector should target the hidden input, not the visible button.

## Gotchas and edge cases

- **Hidden file inputs**: Many sites hide the `<input type="file">` and show a styled button instead. Your selector must target the actual `<input>` element, not the decorative button. Inspect the DOM to find it.
- **Drag-and-drop upload zones**: This action only works with native `<input type="file">` elements. For drag-and-drop upload areas that don't use a file input, you may need a different approach (e.g., using the `coding_agent` to interact with the drop zone's JavaScript API).
- **File must exist**: If the specified file doesn't exist in the expected location (session directory or storage), the step will fail. Ensure the filename matches exactly, including extension.
- **Multiple file inputs**: If the page has more than one file input, make sure your selector is specific enough to target the correct one.
