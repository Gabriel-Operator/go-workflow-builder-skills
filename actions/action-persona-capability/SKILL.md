# Persona Capability

## Offline behavior

Read [contract v1](references/offline-runtime-v1.md). Resolve the delegated Persona capability and recursively classify its playbook, agent nodes, data adapters, and external actions. Delegate locally only when the complete dependency report is compatible; otherwise persist the blocker paths.

## Action type

- **action_type**: `persona_capability`
- **Requires browser**: No

## What it does

This action preserves a persona slash command's native runtime behind a git-backed
Operator step. It does not rewrite Canvas, retained-computer, tool, or endpoint
semantics. The runner validates the page/action relationship and delegates using
the run's requester, page, and chat-session context.

Canvas variants either remain one terminal compatibility step or expand an inline
playbook into one editable Operator step per Canvas task. Expanded task steps share
`canvasTask.sequenceId`; only the terminal task launches the independent child
execution, using its synchronized `aggregateCanvas` playbook. Other variants return
structured variables that later steps can use.
Automatic retries are disabled for this action to avoid repeating side effects.

For every Canvas variant, set `execution.canvas.blueprintRef` to `"inline"`. On an
expanded sequence, also set the terminal `canvasTask.aggregateCanvas.blueprintRef`
to `"inline"`. Never use `"page"` or a named value such as a sequence/product id.
Use `canvasTask.sequenceId` for stable identity. The page/master-skill Canvas path is
deprecated runtime compatibility and must not be generated by coding agents.

## Required fields

| Field | Type | Description |
|-------|------|-------------|
| `step_number` | number | Sequential step position |
| `action_type` | string | Must be `"persona_capability"` |
| `stepId` | string | Unique ID in `step-XXXXX` format |
| `timestamp` | number | Unix timestamp in milliseconds |
| `label` | string | Short display label |
| `intent` | string | Input, processing, and output contract |
| `personaCapabilityConfig` | object | Native runtime configuration |
| `personaCapabilityConfig.schemaVersion` | number | Must be `1` |

| `personaCapabilityConfig.execution` | object | Original normalized execution payload; `type` must match `kind` |
| `personaCapabilityConfig.execution.canvas.blueprintRef` | string | Required for Canvas capabilities and must be `"inline"`. Page/master-skill mode is deprecated and forbidden for workflow authoring. |

## Variant schemas

| `kind` | Required `execution` fields | Runtime behavior |
|--------|-----------------------------|------------------|
| `tool` | `type: "tool"`, non-empty `toolId` | Invokes only the approved page-native tool and returns structured tool results |
| `canvas_task_execution` | `type: "canvas_task_execution"`, `canvas` object | A single compatibility step must be terminal. Expanded task cards contain one `execution.canvas.taskTypes` entry; only the terminal card delegates with the full `canvasTask.aggregateCanvas`. Form-fill Collect tasks use `responseCollection.mode: "channels_only"`; see **workflow-builder** Rule 4 for Answer here / Talk / Chat and draft prefill |
| `sandbox_skill_run` | `type: "sandbox_skill_run"`, non-empty `skillIds`; optional `timeoutSeconds`, `sandboxAgentGroupId`, `modelProfile`, `modelOverridePolicy` | Reuses the retained persona workspace and returns artifacts/variables |
| `workflow_endpoint` | `type: "workflow_endpoint"`, non-empty `endpointSlug`; optional `appId`, `inputs` | Invokes the existing endpoint synchronously and exposes its output |

## Sandbox-backed Canvas tasks

A Canvas task may delegate its computation to the retained sandbox while Canvas
continues to own progress, artifacts, approval, retry, skip, replay, and web/mobile
presentation:

```json
{
  "id": "website-capture-brief",
  "label": "Website Capture & Creative Brief",
  "description": "Capture public website evidence and create the production brief.",
  "artifactType": "text_document",
  "execution": {
    "type": "sandbox_skill_run",
    "skillIds": [
      "bundled:hyperframes-product-explainer",
      "bundled:product-explainer-hardening"
    ],
    "timeoutSeconds": 1500,
    "sandboxAgentGroupId": "product-explainer-video",
    "modelProfile": {
      "textModel": "approved-text-model",
      "ttsProviderConfigId": "saved-ai-resource",
      "ttsModel": "approved-tts-model",
      "ttsVoice": "approved-voice",
      "transcriptionModel": "approved-transcription-model"
    },
    "modelOverridePolicy": {
      "enabled": true,
      "allowed": {
        "textModel": ["approved-text-model", "approved-alternate-text-model"]
      }
    }
  },
  "requiresApproval": true
}
```

The model profile stores only opaque model/provider configuration identifiers;
credentials remain in AI Resources. Runtime overrides are accepted only from the
persona owner or an authorized workspace administrator, and every requested value
must appear in that field's `modelOverridePolicy.allowed` list.

The retained skill must end with one `SANDBOX_RUN_RESULT` containing every output
artifact. Canvas persists those files before it opens its native approval gate, so
one sandbox stage may return text, image, audio, video, PDF, archive, and generic
file artifacts even though `artifactType` declares its primary output.

## Pipeline-backed structured presentation tasks

Use `execution.type: "pipeline_transition"` when Canvas orchestrates a governed
pipeline. Every task names one transition, the expected source/destination
stages, and `operation: "start"` for the first task or `"advance"` thereafter.

Before wiring a task to a `transitionId`, confirm that transition already has
`"automation": { "autoFireOnEntry": false }` set on the **pipeline** side
(`assets/pipeline.json`, `pipeline-builder` skill). This is checked at
execution time, not authoring time — a task that references a transition
missing this field wires up cleanly and still fails the first time chat runs
it, with `Canvas-driven transitions must explicitly set autoFireOnEntry to
false.` (`CANVAS_TRANSITION_AUTO_FIRES`). This file cannot set the field
itself; it can only point at a transition that already has it.

Questions and answer review are not artifacts:

```json
{
  "presentation": {
    "kind": "schema_form_answer_review",
    "questionsField": "form_fields",
    "answersField": "normalized_answers"
  },
  "artifactPolicy": "none",
  "requiresApproval": true,
  "autoApprove": false
}
```

Use `schema_form_questions` for an analysis/questionnaire task. Use
`explicit_only` only on the external execution task, with explicit `image` and
`video` mappings for private screenshots and recording. Set
`playbookEntrypointId: "execute"` only on that final task. Never map URLs,
questions, answers, fingerprints, dry-run data, transition summaries, or
playbook JSON as user-visible artifacts.

## Duration-chunked Canvas media sequences

An expanded Canvas playbook may keep four editable templates—story, storyboard,
video, and stitch—while materializing the storyboard/video pair once per requested
segment at launch. Put `taskSequence` on the shared Canvas configuration and on
the terminal `canvasTask.aggregateCanvas`:

```json
{
  "schemaVersion": 1,
  "type": "duration_chunked_media",
  "durationInputKey": "trailerDurationSeconds",
  "defaultDurationSeconds": 60,
  "minDurationSeconds": 10,
  "maxDurationSeconds": 60,
  "segmentDurationSeconds": 10,
  "storyTaskId": "movie-story",
  "storyboardTemplateTaskId": "scene-storyboard-template",
  "videoTemplateTaskId": "scene-video-template",
  "stitchTaskId": "assemble-trailer",
  "continuity": "previous_video_last_frame"
}
```

The storyboard and video templates may use `{sceneNumber}`, `{sceneCount}`,
`{sceneStartSeconds}`, `{sceneEndSeconds}`, `{durationSeconds}`, and
`{segmentDurationSeconds}` in their labels and descriptions. The runtime creates
stable `scene-01-storyboard` / `scene-01-video` task IDs, makes each later
storyboard depend on the previous video, extracts the approved video's final
frame, and supplies it as the next scene's storyboard reference and required
video first frame.

The stitch template uses this Canvas task execution:

```json
{
  "type": "stitch_videos",
  "sourceTaskIds": [],
  "outputProfile": "1080p_30",
  "audioPolicy": "keep"
}
```

`sourceTaskIds` may be empty in the authoring template; the materializer fills it
with every generated scene-video task in order.

## Gotchas

- Keep `personaCapabilityConfig` at the step root; never put it under `arguments`.
- `kind` and `execution.type` must match.
- Always use `blueprintRef: "inline"` for workflow Canvas. `"page"` and custom values are invalid authoring output.
- Keep expanded Canvas task cards contiguous and in one `canvasTask.sequenceId`.
- A non-terminal expanded Canvas task prepares its stage without launching a child run.
- The terminal Canvas task must remain the final enabled workflow step and its `aggregateCanvas.taskTypes` must include the complete synchronized sequence.
- A duration sequence's four task IDs must refer to tasks present in the terminal aggregate; the stitch task must use `execution.type: "stitch_videos"`.
- A Canvas task type may set `allowSkip: true`; this creates a review gate whose web and mobile forms offer “Skip this step.” Omit it for mandatory tasks.
- Canvas sandbox tasks must declare at least one skill and use a timeout from 60 through 1800 seconds.
- A model override policy is author-only configuration. Never place credentials or arbitrary consumer-provided model strings in a workflow.
- Do not enable generic automatic retries. Add an explicit confirmation or recovery step when needed.
- The workflow must still begin with a browserless `navigate` step according to the top-level workflow-builder contract.
